# قارئ المدرسة — منصة مسابقة التلاوة القرآنية

> «رتّل وارتقِ… واجعل صوتك بالقرآن يتألّق»

منصة كاملة وقابلة للنشر لإدارة مسابقة التلاوة بين طلاب المدرسة: تسجيل الطلاب، رفع مقاطع التلاوة، مراجعة اللجنة، النشر، تصويت الجمهور، ولوحة إدارة متكاملة.

- **بلا أي تبعيات خارجية**: Node.js فقط (الإصدار 22.13 أو أحدث)، ولا حاجة لـ `npm install`.
- **قاعدة بيانات SQLite مدمجة** في ملف واحد، ويسهل نسخها احتياطيًا.
- **تخزين محلي أو سحابي** متوافق مع S3 (Cloudflare R2، AWS S3، Backblaze B2، Wasabi، DigitalOcean Spaces).
- **تصويت موثّق**، و**لجنة تحكيم**، و**نتائج** بثلاثة أوضاع، وتصدير **Excel**.

## اختيار التقنيات

| الطبقة | المستخدم | لماذا |
|---|---|---|
| الخادم | **Node.js 22** دون أي حزمة خارجية | لا توجد تبعيات قد تحمل ثغرات أمنية، ولا خطوة بناء، ويعمل على أي استضافة |
| قاعدة البيانات | **SQLite** المدمجة (ملف واحد) | معاملات وقيود فريدة حقيقية تضمن عدم تكرار الصوت، وأداء أكثر من كافٍ لمدرسة فيها آلاف الطلاب، ونسخ احتياطي بنسخ ملف |
| الواجهة | HTML و CSS و JavaScript عادية | سريعة على الجوال، ولا تحتاج بناء، وسهلة التعديل لأي مطور |
| الفيديو | قرص الخادم، أو **Cloudflare R2** (متوافق مع S3) | R2 لا يحتسب رسومًا على مشاهدة المقاطع (الخروج مجاني)، وهذا هو البند الأغلى عادة في مواقع الفيديو |
| الشبكة | **Cloudflare** أمام الخادم | HTTPS مجاني، وحماية من الهجمات، وتخزين مؤقت للملفات الثابتة |
| الدخول المدرسي | OpenID Connect (Google أو Microsoft) | دون مكتبات، ويُتحقق من التوقيع محليًا |

**لماذا لم أستخدم React و Tailwind و Supabase المقترحة؟**
- **منصة تعمل الآن ومختبرة بالكامل:** بيئة العمل التي بُنيت فيها المنصة لا تسمح بتثبيت حزم npm. والبنية الحالية تحقق كل المتطلبات الوظيفية والأمنية وتعمل دون إعداد خارجي.
- **ضمان «صوت واحد» في مكان واحد:** يُفرض بقيد في قاعدة البيانات داخل خادم واحد تتحكم فيه، لا بسياسات موزّعة على خدمة خارجية.
- **باقة Supabase المجانية لا تناسب مسابقة حقيقية:** تتوقف بعد أسبوع من الخمول، وفيها 1 جيجابايت فقط لتخزين الملفات، والباقة المدفوعة تبدأ من 25 دولارًا شهريًا.
- **الانتقال إلى PostgreSQL أو Supabase لاحقًا ممكن:** استعلامات SQL في المنصة قياسية ومجمّعة في ملفات `src/`. لكنه **يتطلب إعادة كتابة طبقة الوصول للبيانات** وتعديلًا كاملًا لإعدادات المشروع، وليس تغييرًا في الإعدادات فقط.

## التكاليف المتوقعة (تقديرية — راجع الأسعار الحالية قبل الاشتراك)

| البند | الخيار | السعر وقت كتابة الدليل (نوفمبر 2026) |
|---|---|---|
| الخادم | VPS صغير (مثل Hetzner بمعالجين و4 جيجابايت ذاكرة) | نحو 4–6 يورو شهريًا، وقد رفعت Hetzner أسعارها في 2026 |
| الخادم (بديل مُدار) | Render Starter + قرص دائم | 7 دولارات شهريًا + 0.25 دولار لكل جيجابايت، وباقته المجانية لا تدعم الأقراص |
| تخزين المقاطع | Cloudflare R2 | أول 10 جيجابايت مجانًا شهريًا، ثم 0.015 دولار لكل جيجابايت، والمشاهدة (الخروج) مجانية |
| Cloudflare (DNS و HTTPS والحماية) | الباقة المجانية | 0 |
| النطاق (Domain) | أي مسجّل نطاقات | نحو 10–15 دولارًا سنويًا |

**مثال واقعي:** 150 مشاركًا بمتوسط 40 ميجابايت للمقطع، أي نحو 6 جيجابايت، تبقى ضمن باقة R2 المجانية. فتكون التكلفة الشهرية قرابة **5 يورو للخادم فقط** (أو 7–10 دولارات على Render)، مهما كثرت المشاهدات.

## ما تحتاج إلى إعداده بنفسك (خارج الكود)

1. **استضافة بقرص دائم:** خادم VPS، أو Render / Railway / Fly.io مع قرص على المسار `/data`. يجب أن يحتفظ القرص بقاعدة البيانات بين عمليات إعادة النشر.
2. **نطاق + Cloudflare:** وجّه النطاق إلى الخادم عبر Cloudflare، واختر نمط SSL «Full (strict)»، ثم عيّن `TRUST_PROXY=1` و `PUBLIC_URL`. الرفع يتم بأجزاء حجم كل منها 4 ميجابايت، فلا يصطدم بحد Cloudflare لحجم الطلب.
3. **حاوية R2 (موصى بها):** أنشئ حاوية **خاصة** (لا تفعّل الوصول العام)، ومفتاح API بصلاحية «Object Read & Write» لهذه الحاوية فقط، ثم ضع القيم في `S3_*` مع `STORAGE_DRIVER=s3`. ما لم تفعل ذلك، تُخزَّن المقاطع على قرص الخادم.
4. **حساب المالك:** `ADMIN_USERNAME` و `ADMIN_PASSWORD` في `.env` عند أول تشغيل، ثم احذف كلمة المرور من الملف.
5. **مفتاح سري:** `APP_SECRET`، وهو 64 حرفًا عشوائيًا. أو اتركه ليُنشأ تلقائيًا، و**احتفظ بنسخة من ملف `data/.secret`**؛ فبدونه تبطل الرموز الشخصية وروابط المقاطع.
6. **(اختياري) الدخول بحساب المدرسة:** أنشئ تطبيق OAuth في Google Cloud Console أو Microsoft Entra، وسجّل عنوان إعادة التوجيه `<PUBLIC_URL>/auth/school/callback`، ثم املأ `OIDC_*`. لم يُختبر هذا المسار مع مزوّد حقيقي بعد.
7. **نسخ احتياطي دوري** لمجلد البيانات (انظر أدناه).
8. **(اختياري) استضافة الخطوط محليًا:** تُحمَّل الخطوط حاليًا من Google Fonts، وهذا يكشف عناوين الزوار لـ Google. للخصوصية القصوى نزّل خطوط Amiri و Reem Kufi و Tajawal، وضعها في `public/fonts`، وعدّل وسم الخطوط في رأس الصفحات.

## النسخة التجريبية (بيانات وهمية منفصلة)

```bash
npm run demo            # ينشئ data-demo/ ببيانات وهمية ثم يشغّل الخادم عليها
npm run demo -- --reset # يعيد إنشاءها
```

- قاعدة بيانات **مستقلة** في `data-demo/`، ويرفض السكربت العمل على أي قاعدة بيانات غير موسومة بأنها تجريبية.
- يظهر شريط «نسخة تجريبية» في كل صفحات الموقع ولوحة الإدارة.
- تتضمن: 12 مشاركًا وهميًا بمقاطع مولّدة، و60 طالبًا مؤهلًا مع رموزهم الشخصية في `data-demo/demo-pins.csv`، و3 محكّمين مع تقييماتهم، وأصواتًا تجريبية.
- الحسابات: `demo / Demo2026pass` (المالك)، و `judge1` و `judge2` و `judge3` بكلمة المرور `Judge2026pass`.

## التشغيل السريع (على جهازك)

```bash
cp .env.example .env          # ثم عدّل ADMIN_USERNAME و ADMIN_PASSWORD
npm start                     # أو: node server.js
```

افتح `http://localhost:3000`، ولوحة الإدارة على `http://localhost:3000/admin`.

يمكن أيضًا إنشاء حساب المالك يدويًا:

```bash
npm run create-admin
```

يُنصح بتثبيت **ffmpeg** على الخادم (موجود تلقائيًا في Docker). عند توفّره تتحقق المنصة من مدة كل مقطع ووجود الصوت فيه من الخادم، وتنشئ له صورة مصغّرة. وبدونه تعمل المنصة لكنها تعتمد على المدة التي يقرؤها المتصفح.

## النشر على الإنترنت

### الخيار 1: Docker على خادم VPS (موصى به)

```bash
cp .env.example .env   # عدّل القيم
docker compose up -d --build
```

ضع أمامه Nginx أو Caddy مع شهادة HTTPS، وعيّن `TRUST_PROXY=1`. مثال Caddy:

```
qari.example.com {
  reverse_proxy localhost:3000
  request_body { max_size 2GB }
}
```

مع Nginx أضف `client_max_body_size 10m;`، فالرفع يتم بأجزاء صغيرة حجم كل منها 4 م.ب.

### الخيار 2: Render أو Railway أو Fly.io

1. ارفع المجلد إلى مستودع GitHub.
2. أنشئ خدمة ويب من الـ Dockerfile.
3. أضف **قرصًا دائمًا (Persistent Disk / Volume)** على المسار `/data`. هذه الخطوة ضرورية، وإلا تُفقد البيانات عند كل إعادة نشر.
4. أضف متغيرات البيئة من `.env.example`.

> ⚠️ لا تعمل المنصة على Vercel أو Netlify Functions، لأنها تحتاج خادمًا مستمرًا وقرصًا دائمًا.

### تفعيل التخزين السحابي (Cloudflare R2 مثلًا)

```
STORAGE_DRIVER=s3
S3_ENDPOINT=https://<ACCOUNT_ID>.r2.cloudflarestorage.com
S3_REGION=auto
S3_BUCKET=qari-videos
S3_ACCESS_KEY_ID=...
S3_SECRET_ACCESS_KEY=...
```

يبقى الحاوي (Bucket) **خاصًا**، ويُشغَّل كل فيديو عبر رابط موقّع مؤقت صالح لساعة واحدة. في هذا الوضع تبقى قاعدة البيانات وحدها على القرص المحلي.

## نظام التصويت

### 1) تجهيز قائمة الطلاب المؤهلين
من **لوحة الإدارة ← الطلاب المؤهلون للتصويت** استورد ملف CSV (يُحفظ من Excel بصيغة «CSV UTF-8») بالأعمدة:

```
الرقم المدرسي,الاسم,الصف,الشعبة,البريد المدرسي
```

يجب أن تطابق أسماء الصفوف ما في الإعدادات. البريد اختياري، ويلزم فقط في طريقة «حساب المدرسة».

### 2) طريقة التحقق من الهوية (الرقم المدرسي وحده لا يكفي)
- **رمز شخصي سري (الافتراضي):** تصدر الإدارة لكل طالب رمزًا من 6 خانات، وتطبعه في بطاقات وتوزّعه بشكل فردي. يُخزَّن الرمز مشفّرًا ولا يُعرض إلا مرة واحدة عند الإصدار، ويُقفل دخول الطالب 30 دقيقة بعد 5 محاولات خاطئة.
- **حساب المدرسة (Google Workspace أو Microsoft 365):** اضبط متغيرات `OIDC_*` في `.env`، وسجّل عنوان إعادة التوجيه `<PUBLIC_URL>/auth/school/callback` في Google Cloud Console أو Microsoft Entra، ثم اختر هذه الطريقة من الإعدادات. يُطابَق البريد مع القائمة المعتمدة، ويُقصر الدخول على نطاق بريد المدرسة. ⚠️ لم يُختبر هذا المسار مع حساب حقيقي بعد، فجرّبه بحساب تجريبي قبل يوم التصويت.

### 3) ضمانات الاحتساب (كلها في الخادم وقاعدة البيانات)
- قيد فريد في قاعدة البيانات: **صوت صحيح واحد لكل طالب في الموسم**، مهما اختلف الجهاز أو المتصفح، وحتى مع الطلبات المتزامنة.
- يتم التحقق من حالة التصويت ومن اعتماد المتسابق ومنع التصويت للنفس وقيد الفئة في معاملة واحدة على الخادم.
- يُفتح التصويت ويُغلق تلقائيًا حسب المواعيد، أو يدويًا من «إدارة التصويت».
- النتائج وأعداد الأصوات **مخفية عن الطلاب أثناء التصويت**.
- تعديل الصوت ممنوع افتراضيًا، ويمكن السماح به من الإعدادات. عند التعديل يُحفظ الصوت السابق بحالة «معدّل» ولا يُحذف.
- **سجل المحاولات المرفوضة** للإدارة فقط: رمز خاطئ، تكرار، تصويت للنفس، خارج الموعد، نشاط آلي، وغيرها.
- **سرّية الاقتراع:** لا تظهر هوية المصوّت لأي مشرف إلا لصاحب صلاحية «إدارة الأصوات» التي يمنحها المالك. وأي إلغاء أو استعادة لصوت يتطلب هذه الصلاحية مع سبب إلزامي يُسجَّل في سجل العمليات.
- الحماية من الطلبات الآلية: تحديد معدل الطلبات لكل عنوان ولكل طالب، ومصيدة للروبوتات، وحماية من الطلبات القادمة من مواقع أخرى.

## لجنة التحكيم

- أنشئ حسابات بصلاحية **«محكّم»** من «المشرفون والمحكّمون».
- المعايير الافتراضية: أحكام التجويد 40، وسلامة الحفظ والتلاوة 30، وجمال الصوت والأداء 20، والوقف والابتداء 10. يمكن تعديلها من الإعدادات، لكنها **تُقفل بعد اعتماد أول تقييم** حتى لا تتغير قواعد الاحتساب أثناء التحكيم.
- التكليف: كل محكّم يقيّم جميع التلاوات المعتمدة، أو يُكلَّف بتلاوات محددة يدويًا.
- لا يرى المحكّم الرقم المدرسي ولا الاسم الكامل، ولا يرى تقييمات زملائه **إلا بعد اعتماد تقييمه**. التقييم المعتمد مقفل، ولا تعيد الإدارة فتحه إلا مع تسجيل سبب.
- **درجة التحكيم** = متوسط (مجموع درجات المحكّم ÷ الدرجة العظمى × 100) للتقييمات **المعتمدة** فقط. لا تُحتسب المسودات.
- **التقييمات الناقصة:** يُعدّ تحكيم المتسابق مكتملًا عندما يعتمد جميع المحكّمين المكلّفين تقييماتهم، أو عند بلوغ حد أدنى تحدده الإدارة. ولا يمكن اعتماد النتائج ما دام أي متسابق ناقص التحكيم.

## تحديد الفائزين

| الوضع | الترتيب |
|---|---|
| تصويت الطلاب فقط | الأعلى في الأصوات الصحيحة |
| لجنة التحكيم فقط | الأعلى في متوسط التحكيم المعتمد |
| مختلط (افتراضيًا 70/30) | النهائية = 70% × درجة التحكيم + 30% × نسبة التصويت |

**نسبة التصويت** = أصوات المتسابق ÷ مجموع الأصوات الصحيحة في فئته × 100. ويوجد خيار بديل يحسب النسبة إلى أعلى متسابق في الفئة.

> ملاحظة: مع كثرة المتسابقين تصغر نسب التصويت المحسوبة من المجموع. فإذا تنافس 10 متسابقين فمتوسط النسبة 10% تقريبًا، فيصبح أثر التصويت أقل من وزنه المعلن. الخيار البديل يعطي المتسابق الأعلى أصواتًا 100%، فيتضح أثر التصويت أكثر.

**قواعد التعادل المعلنة (الوضع المختلط):**
1. الدرجة النهائية الأعلى.
2. ثم متوسط التحكيم الأعلى.
3. ثم الأصوات الصحيحة الأكثر.
4. ثم درجة المعيار الأول للتحكيم.
5. إن بقي التعادل، يتشارك المتسابقان المركز.

تُعرض المعادلة لكل متسابق في لوحة الإدارة وفي ملف Excel.

**الإعلان:** لا يمكن اعتماد النتائج إلا بعد إغلاق التصويت واكتمال التحكيم. يحفظ الاعتماد لقطة ثابتة من النتائج، ولا يُعلن للجمهور إلا هذه اللقطة، وبالاسم المعتمد للنشر فقط. ويمكن تحديد الفائزين لكل فئة أو على مستوى المدرسة كلها.

| المراجع | مراجعة المشاركات، ومتابعة التحكيم والنتائج |
| المحكّم | تقييم التلاوات المكلَّف بها فقط |

## الأمان والخصوصية

- كلمات مرور المشرفين والرموز الشخصية للطلاب مشفّرة.
- جلسات `HttpOnly`، مع رمز CSRF وفحص لمصدر الطلب، ورؤوس أمان (CSP و HSTS).
- يُفحص المحتوى الفعلي لكل ملف مرفوع ولا يُكتفى بامتداده، وروابط الفيديو موقّعة ومؤقتة.
- يتوفر تصدير بصيغتي Excel و CSV للمتسابقين والنتائج والطلاب، ويُسجَّل كل تصدير.

- **المقاطع غير المعتمدة لا تُعرض للعامة:** رابط المقطع العام يتوقف فورًا إذا أُلغي اعتماده، حتى لو كان الرابط ما زال ساريًا. ولصاحب المشاركة رابط معاينة خاص.
- **إزالة البيانات الوصفية من كل فيديو مرفوع**، ومنها موقع التصوير GPS واسم الجهاز، مع تحويل MOV إلى MP4.
- **النتائج للجمهور:** تُعلن أسماء الفائزين فقط دون أرقام تفصيلية افتراضيًا، ولا تُعرض هويات المصوّتين للجمهور مطلقًا.
- **سياسة الخصوصية:** صفحة قابلة للتعديل من الإعدادات، مع مدة احتفاظ معلنة وتنبيه في لوحة الإدارة عند انتهائها.
- **إدارة البيانات:** حذف مقاطع المرفوضين، وحذف التسجيلات المهجورة، وأرشفة مقاطع الموسم (مع الإبقاء على تلاوات الفائزين اختياريًا)، وحذف موسم بالكامل (للمالك). كل ذلك يُسجَّل.
- **موافقة ولي الأمر:** نصها قابل للتعديل وفق سياسة المدرسة، ويُحفظ وقت الموافقة.

> لا يمكن لأي موقع منع التنزيل منعًا مطلقًا؛ الروابط المؤقتة وإخفاء زر التنزيل تمنع التنزيل السهل فقط.

## إعلان الفائزين والشهادات

- **صفحة `/results` احتفالية:** منصة تتويج، وأوسمة ذهبية وفضية وبرونزية، ومؤثرات بصرية هادئة بلا صوت، وتلاوات الفائزين. لا تظهر إلا بعد اعتماد النتائج وإعلانها من الإدارة.
- **«طباعة النتائج / حفظها PDF»:** يطبع نسخة رسمية مرتبة من النتائج.
- **الشهادات:** شهادة **مشاركة** لكل تلاوة معتمدة، وشهادة **تفوّق** للفائزين بعد الإعلان، بصيغة PDF. ينزّلها الطالب من «متابعة التسجيل»، وتصدرها الإدارة من نافذة المتسابق.
- **التحقق من الشهادة:** لكل شهادة رمز تحقق، ويمكن لأي جهة التأكد من صحتها عبر صفحة `/verify`.

## الترقية من الإصدار الأول

عند تشغيل الإصدار الجديد على قاعدة بيانات قديمة تُرحَّل البيانات تلقائيًا: تبقى المشاركات والمقاطع كما هي، وتُنقل أصوات الإصدار الأول (التي كانت مرتبطة بالأجهزة أو الرموز العامة) إلى جدول أرشيف `votes_legacy_v1` ولا تُحتسب. ويبدأ التصويت الموثّق من الصفر.

## النسخ الاحتياطي

انسخ مجلد `DATA_DIR` كاملًا، وفيه `qari.db` و`.secret` ومجلد `media` في حال التخزين المحلي. من الأفضل إيقاف الخادم أثناء النسخ، أو استخدم:

```bash
sqlite3 data/qari.db ".backup backup.db"
```

## موسم جديد

من **الإعدادات ← رمز الموسم** غيّر الرمز (مثلًا من 1448 إلى 1449)، فتبدأ مسابقة جديدة فارغة وتبقى بيانات المواسم السابقة محفوظة.

## الاختبار

```bash
BASE=http://localhost:3000 ADMIN_USER=admin ADMIN_PASS=... npm test -- path/to/video.mp4
```

يختبر هذا الأمر المسار الكامل: التسجيل، والرفع مع الاستئناف، والمراجعة، والتحقق من هوية المصوّت، ومنع التكرار والتصويت للنفس، والتحكيم، ومعادلة النتائج، والاعتماد، والاستبعاد، والتصدير. شغّله على **قاعدة بيانات فارغة** في نسخة تجريبية، لا على موقع المسابقة الحقيقي.
